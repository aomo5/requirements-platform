# 接口契约模板

Use this template when creating a new lightweight API contract. Keep it practical: enough for frontend, backend, and testing to start work without guessing.

```markdown
# {功能名称}-接口契约

## 1. 文档说明

- 来源需求：`{需求文档路径}`
- 原型页面：`{Paper/Figma/原型链接或页面名称}`
- 任务拆分：`{任务拆分路径}`
- 适用范围：`{前端/后端/第三方/导出等}`
- 文档状态：`建议方案 / 待前后端评审确认 / 已确认`
- 评审模式：轻量两人评审，前端负责人 1 人、后端负责人 1 人

本文档用于在开发前确认前端页面所需接口能力、字段、枚举、错误提示、分页、导出和 Mock 数据口径。它不是最终 Swagger / OpenAPI 文档，但应作为前后端联调和接口落地的评审清单。

## 2. 契约原则

| 原则 | 说明 |
|------|------|
| 后端权威校验 | 业务校验以后端结果为准 |
| 金额单位 | 接口金额字段统一使用 `{分/元/待确认}` |
| 枚举稳定 | 前端不通过中文文案判断业务类型，应使用后端返回的枚举值 |
| 历史兼容 | 老数据缺少新字段时，前端和后端的默认处理需要明确 |
| 错误原样提示 | 后端业务错误返回可展示文案，前端优先原样展示 |
| 页面与导出一致 | 页面字段、导出字段、汇总口径使用同一字段定义 |

### 2.1 两人评审分工

| 角色 | 主要确认内容 | 产出 |
|------|--------------|------|
| 前端负责人 | 页面是否够用、字段是否能渲染、枚举是否稳定、错误文案是否能直接展示、Mock 是否能支撑开发 | 标记前端无阻塞项，或列出缺失字段/交互依赖 |
| 后端负责人 | 接口是否复用或新增、字段是否可实现、校验放在哪个接口、错误码是否可落地、金额单位是否统一 | 标记后端无阻塞项，或列出接口/字段/校验调整 |

### 2.2 状态口径

| 状态 | 含义 |
|------|------|
| 建议方案 | 当前是产品/需求整理出的推荐方案，评审时可调整 |
| 复用确认 | 倾向复用现有接口，需要确认筛选条件、返回字段或权限 |
| 需扩展 | 现有接口可承接，但需要新增字段、校验或返回结构 |
| 待接口归属确认 | 不确定复用现有接口还是新增接口，需要后端拍板 |
| 待字段命名确认 | 业务口径已明确，但字段名、枚举值或单位还未最终确认 |
| 待开放范围确认 | 能力是否允许编辑、导出或批量处理还需确认 |
| 待确认 | 已识别需要评审，但暂未细分到具体状态 |
| 已确认 | 前后端已经同意，可按契约开发 |

## 3. 页面接口清单

### 3.1 {页面/模块名称}

| 页面/区域 | 场景 | 接口能力 | 前端用途 | 当前接口/候选接口 | 负责人 | 状态 | 评审结论 | 确认日期 |
|-----------|------|----------|----------|-------------------|--------|------|----------|----------|
| {区域} | {场景} | {能力} | {用途} | `{METHOD /path}` 或候选接口 | {负责人} | {状态} | 待评审 | - |

## 4. 字段契约

### 4.1 列表/详情返回字段

| 字段名 | 中文含义 | 类型 | 单位 | 是否必返 | 默认/空值处理 | 前端展示/用途 | 备注 |
|--------|----------|------|------|----------|----------------|----------------|------|
| `{field}` | {含义} | {type} | {unit} | {是/否/条件必返} | {默认值} | {用途} | {备注} |

### 4.2 创建/更新请求字段

| 字段名 | 中文含义 | 类型 | 是否必传 | 校验规则 | 备注 |
|--------|----------|------|----------|----------|------|
| `{field}` | {含义} | {type} | {是/否/条件必传} | {规则} | {备注} |

## 5. 枚举契约

### 5.1 `{enumName}`

| 枚举值 | 中文 | 前端展示 | 说明 |
|--------|------|----------|------|
| `{VALUE}` | {中文} | {展示文案} | {说明} |

## 6. 金额/时间/单位字段契约

| 字段名 | 中文含义 | 类型 | 单位/格式 | 是否必返 | 前端展示 |
|--------|----------|------|-----------|----------|----------|
| `{amountField}` | {含义} | number | 分 | 是 | {展示名称} |
| `{timeField}` | {含义} | string | `YYYY-MM-DD HH:mm:ss` | 是 | {展示名称} |

## 7. 错误码与提示文案契约

| 场景 | 建议错误码 | 后端业务含义 | 前端展示文案 | 状态 |
|------|------------|--------------|--------------|------|
| {场景} | `{ERROR_CODE}` | {含义} | {可展示文案} | {状态} |

## 10. Mock 示例

### 10.1 成功返回

```json
{
  "code": 0,
  "data": {},
  "msg": ""
}
```

### 10.2 关键失败返回

```json
{
  "code": 400001,
  "msg": "可直接展示给用户的错误文案",
  "data": null
}
```

## 11. 前后端评审检查清单

| 检查项 | 主确认人 | 状态 | 评审结论 | 确认日期 |
|--------|----------|------|----------|----------|
| 是否确认新增字段最终命名 | 前端负责人、后端负责人 | 待字段命名确认 | 待评审 | - |
| 是否确认金额/时间/单位 | 前端负责人、后端负责人 | 建议方案 | 待评审 | - |
| 是否确认接口复用或新增 | 后端负责人 | 待接口归属确认 | 待评审 | - |
| 是否确认错误码和提示文案 | 后端负责人 | 需扩展 | 待评审 | - |
| 是否确认页面、导出、Mock 字段一致 | 前端负责人、后端负责人 | 需扩展 | 待评审 | - |
| 是否确认最终 Swagger / Apifox / YApi / OpenAPI 更新责任人 | 后端负责人 | 待确认 | 待评审 | - |

| 日期 | 变更人 | 变更内容 | 影响范围 |
