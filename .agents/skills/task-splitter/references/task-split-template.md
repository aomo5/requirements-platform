# 任务拆分模板

当用户希望输出一份“结合仓库现状的正式任务拆分文档”时，优先使用这个模板。

## 标题

[功能名称]-任务拆分

## 1. 文档归档信息

- 来源 PRD
- 建议任务文档路径
- 对应代码模块
- 关联模块

## 2. 当前代码环境理解

- 已有相关模块
- 可复用能力
- 候选代码落点
- 当前限制或技术包袱
- 当前仓库是否包含前端工程

## 3. 拆分原则

- 一级按什么业务交付单元拆
- 二级按什么任务类型打标
- 哪些任务可以并行
- 哪些任务必须串行

## 4. 任务总览

建议使用表格，至少包含：

- 任务 ID
- 任务名称
- 任务类型
- 优先级
- 主要模块
- 前置依赖
- 预期产出

## 5. 详细任务拆分

每个任务至少写清：

- 任务类型
- 目标
- 范围
- 候选代码落点
- 核心改动点
- 完成标志
- 风险或回归关注点

如果是原型任务，补充：

- 页面名称和入口
- 使用角色
- 页面目标
- 页面区块结构
- 查询条件
- 字段 / 卡片 / 图表
- 操作按钮
- 详情 / 弹窗 / 抽屉
- 空状态 / 加载状态 / 失败状态 / 无权限状态
- 权限差异
- 时间和金额口径
- 是否导出

## 6. 测试与验证建议

- 单元或服务层验证
- 关键场景回归
- 统计/展示验证
- 原型确认项
- 历史兼容与上线切换验证

## 7. 建议实施顺序

按推荐顺序列出：

- 先做什么
- 后做什么
- 哪些可以并行推进
