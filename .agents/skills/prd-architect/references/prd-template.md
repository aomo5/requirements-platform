# PRD Template

Use this template when the user asks for a standard product requirement document.

## Title

[Feature name]

## 1. Background

- What business issue or opportunity triggered this requirement
- Why it matters now

## 2. Objective

- What the feature should achieve
- How success will be judged

## 3. Target Users

- Primary users
- Secondary stakeholders

## 4. Problem Statement

- What user or business problem exists today
- What pain point or inefficiency the feature addresses

## 5. Scope

### In Scope

- Included behaviors and modules

### Out of Scope

- Explicit exclusions for this phase

## 6. Detailed Requirements

Write requirements by scenario or module. For each item, specify:

- Trigger
- Preconditions
- Main flow
- System response
- Edge or exception behavior

## 7. Business Rules

- Role restrictions
- Validation rules
- Limits, thresholds, or timing rules

## 8. Acceptance Criteria

- Clear, observable pass/fail criteria

## 9. Data and Reporting Impact

- New fields
- Report/statistics changes
- Audit/logging needs

## 10. Risks and Open Questions

- Pending decisions
- External dependencies
- Known risks
