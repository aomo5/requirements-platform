# 原生流程 CLI

在仓库根目录使用 `npm run flow -- help`。命令和字段见 [流程 CLI](../../../../FLOW_CLI.md)。MySQL 模式下，流程和说明按各自版本一起保存并回读。

## 工作方式

1. 从当前用户链接确定 origin、主题 path 和流程 ID。默认本机 `http://127.0.0.1:8125`，也可配置用户指定的局域网工作台地址。`whoami` 检查会话；首次需要用户在终端运行 `login`，使用原工作台账号，7 天会话复用。不要让用户把密码发到聊天、读取浏览器 Cookie、创建代用户会话或关闭权限。未登录时先完成不依赖在线写入的代码核验或方案准备，再说明一次性登录步骤。
2. `pull --path '模块/功能' --out /tmp/新的草稿.json` 读取最新图与说明。保留 `base`、来源、主题路径和版本，只编辑 `draft`；草稿不是持久化新数据源，不放回已迁移的旧流程 JSON 路径。`show --file ... --flow ... --node ...` 定位原节点、出入线和说明；`list --path ...` 查询流程清单。
3. 写操作 JSON 数组，使用 `patch --file ... --ops ...` 按稳定 ID 批量修改。操作支持 `flow/node/edge/lane/note.add/update/remove`；节点、边、泳道附 `flowId`。新增用 `value`，修改用 `set`/`unset`，删除须同时处理依赖。保留未编辑子流程、说明、坐标和有效引用。可直接用脚本修改 `draft`，但仍走同样的 check/diff/apply，不改 `base` 来消除冲突。
4. `check --file ...` 检查字段、引用、说明与可读性提示；`diff --file ...` 审阅规范化后的逐项差异。新失效引用会阻止提交，既有问题和布局建议为警告，只核本次相关范围。结构检查不证明业务语义或执行结果。
5. `apply --file ... --dry-run` 服务端核双版本、跨主题引用和说明，随后 `apply --file ...` 保存。授权改图时无需再问一次是否保存。两个资源任一失败都会回滚；无修改不升版本；成功自动回读，并把草稿基线更新到已保存版本。
6. 结构、文案或布局变化通常用输出链接核查实际画布；用户明确本轮只核逻辑、不看布局时，不启动浏览器，完成 CLI 结构、引用、调用返回及恢复关系检查，交付注明视觉未核验。不要为默认视觉步骤索取额外登录或扩大范围。需要读图时，遮挡或截断仍用 CLI 修正；简单说明修改可复用原视觉证据。相关规格和评审资料照常维护，文档不属于流程批量接口。

## 操作示例

```json
[
  {"op":"node.update","flowId":"main","id":"notify","set":{"label":"通知与原策略重试","x":200,"y":300}},
  {"op":"edge.update","flowId":"main","id":"edge-one","set":{"target":"audit","label":"耗尽后核验","trace":"proposal"}},
  {"op":"note.update","id":"note-notify","set":{"text":"本次已核实的方法依据与输出范围。"}}
]
```

实际 ID 从新拉取的版本读取，不从示例复制。节点 source/target、事件属性、结束范围、并行语义、颜色与泳道仍采用工作台原生字段，见 [工作台维护](workbench.md)。页面元素说明只能原样透传。

## 失败与恢复

- 401/403：登录或创建者权限问题，不转向直写数据库或借用他人会话。用户在终端完成一次 `npm run flow -- login` 即可，密码无需交给代理。
- 409：整个批次未覆盖，重新 pull 并根据最新内容合并，禁止只更新 expectedRevision 重发旧内容。
- 请求超时：提交结果可能未知，先重新读取核对，不能自动重放。
- `saved:true,verified:false`：服务已确认保存；按输出区分回读失败、并发更新或本地基线未写入，保留已保存版本并重新 pull，不报告“未保存”。
- 缺少 bundle/batch 接口：服务代码需更新或重启。不能把浏览器会话或旧 JSON 作为隐式替代写入通道；先说明具体缺口。

`versions` 读取原历史；回退应从当前版本制作明确反向修改。Mermaid 导出只供阅读，不能无损保留布局、边 ID 和全部样式；原生 JSON 草稿为改图输入。`link` 仅返回定位链接，不自动打开浏览器。

## 团队连接

统一入口 `workbench flow ...` 与原 flow 命令相同。通过 `workbench config --url http://服务器局域网IP:8125` 设置服务，再以自己的账号 `workbench login`；会话按来源隔离，服务端继续检查需求归属。安装包与需求、接口和测试命令见 [WORKBENCH_CLI.md](../../../../WORKBENCH_CLI.md)。
