# 工作台维护

本页说明需求平台的原生流程字段。以当前版本的 [流程 CLI](../../../../FLOW_CLI.md) 和模型校验为准。

- 流程日常编辑默认通过 [CLI 操作](cli.md)：原生数据、图与说明双版本、原子提交和回读均由 CLI 处理；浏览器保留最终读图用途。
- MySQL 模式以工作台中的当前版本为准。按用户提供的入口或项目配置确认服务地址。
- CLI 使用 GET `/api/flows/bundle?path=...` 同事务读取图和说明，POST `/api/flows/batch?path=...` 双版本原子保存；`dryRun:true` 在服务端预检但不写入。旧页面继续使用流程 GET/PUT `/api/flows?path=<主题逻辑路径>`，GET 的 workspace 包含 revision；PUT 带 expectedRevision、applicability、reason、flows、references。保留未编辑对象和稳定 ID；冲突后重读合并，不能强行覆盖。
- 文档 GET/PUT `/api/document?path=...&file=<主题/逻辑文件.md>`，按该文档 revision 提交。保留正文规则标识。
- 节点说明 GET/PUT `/api/annotations?path=...`，按 workspace.revision 提交 notes；flow-node 目标以 flowId/nodeId 关联。删图后检查说明和父子关系，不留孤立引用。
- 核验父子承接时先读取最新保存版本，按子流程的 `parent.entryPath/flowId/nodeId` 定位实际来源节点；逐项对照相关子图输出、父图出边、接收节点及后续去向，再在画布核对对象、条件、连线方向和可读性。已有等价承接时复用，不能依据旧标签页、返回导航或连线文字就认定已接住，也不重复新建节点。
- 节点已有 supplement 布尔样式、variant=branch 紫色分支样式、issues（P01 等问题编号）；连线 trace 可为 actual/proposal/branch；流程 lanes 保存名称、x/y/width/height。以 flow-store.js 校验为准，保持原生可编辑。
- 编辑器“样式与泳道”入口可改所选节点的白/蓝/紫样式、P 编号、所选连线灰实线/红实线/蓝虚线/紫实线，以及泳道名称/范围/增删。泳道是背景分组，修改泳道范围不会自动移动节点；节点位置可用 CLI 的 `node.update` 批量指定 x/y，泳道用 `lane.update`。界面拖动仅作可选交互，不作为代理默认编辑方式。
- API 需遵守服务当前访问控制。涉及外部发布或执行真实业务动作时，按当前任务的授权处理。


### 公共模块与调用数据

- 公共定义为 `flow.kind: "module"`，`parent: null`；普通图继续省略 kind。公共模块可被主图、子图或其他模块调用，归属树不承担调用关系。
- 调用节点使用 `type: "call"` 和 `call: { entryPath, flowId, nodeId, returns: [{ outputNodeId, targetNodeId }] }`。`nodeId` 是模块的 input 入口；`outputNodeId` 是模块 return 节点；`targetNodeId` 是当前调用图内的接收节点，需有真实的调用节点出边承接。逐输出维护映射，不通过 `workspace.references` 假装调用；references 仍只用于外部流程列表引用。
- 模块入口 input 不固定 source 到单一调用者；模块返回使用 `type: "return"`，不写固定 target。返回的业务含义在节点名称与说明中表达，调用上下文决定回哪个调用处。普通 `output.target` 继续用于固定目的地的跨图移交。
- 当前 call 表达同步本次调用，不等待异步业务终态；定时/消息/人工独立执行使用已有 event，在其流程内调用模块。不要把独立事件放在公共定义内后无上下文地 return。
- 模块修改后，核对全部调用点的入口与输出映射；删除模块、入口或返回节点须先处理依赖。UI 跳转按当前调用上下文返回，直接打开定义不能猜一个调用者。CLI check、diff、apply --dry-run 与回读验证字段保真，Mermaid 元数据也须保留。

### 右侧参数与承接说明

用于公共调用、输入、返回及跨图接收的参数含义不清，或用户要求补充右侧契约的场景。工作台已提供节点 `contract` 属性时，字段写入输入／返回参数表，不再只堆入说明文本。业务规则、结果边界和未确认事项保留在说明；普通步骤只列实际使用的字段。关键分支和去向仍须在画布可见，参数表与说明不替代连线及结构化关联。

节点可选属性为 `contract: { inputs: [...], outputs: [...] }`。每行保留稳定 `id`，填写 `name`、`type`、`required`（`required / optional / conditional`）；按需填写 `condition`、`source`、`description`，条件必需必须填写 `condition`。同方向行 ID 不重复，每方向最多 50 行；字段名与类型最多 120 字，条件与来源最多 1000 字，含义最多 2000 字。无参数可以不设 contract，不凭空加占位行。沿用上下文在 source 中说明，不虚构必需的返回载荷。

CLI 的 `show` 直接返回 `node.contract`；用 `node.update` 的 `set.contract` 整体更新该节点的两组字段，修改前保留未调整的行与 ID，经 `check / diff / apply --dry-run / apply` 保存回读。结构化参数、说明和实际映射须一致，未知属性不通过校验。节点复制包含字段表及实际关联；顶部“复制给 AI”仍是资料入口，读取对应 flow 详情才取得完整 contract。Mermaid 元数据随导入导出保留，但第三方渲染不等于展示参数表。

右侧默认以阅读态展示，用“基础属性／参数契约”页签区分原有设置说明与新增参数区；参数契约内同时列出输入、返回和来源承接，不再按输入／返回拆页签。点击“编辑”进入维护。参数表只列字段、类型、必需性；点击字段行查看完整条件、来源和含义，不重复放置详情按钮。长说明保留只读弹窗，查看动作不保存数据。页签只控制当前展示，CLI、节点复制与保存始终保留两组完整字段；未完成参数继续保留草稿，不能因切换或退出编辑丢失。

迁移已有文字参数时只提取已确认字段，按原说明保留条件、来源与时点差异；目标结果分类标目标契约，未定命名不要伪装已有字段。迁移后移除本次重复字段段落，保留用户原备注及有效证据。字段表上线属于工作台能力，不能因此更改业务流程或业务代码。

| 节点职责 | 右侧重点 |
|---|---|
| 输入、模块入口 | 来源、原业务对象、必要输入及进入条件 |
| 调用 | 传入数据、沿用上下文、目标模块入口、各返回结果及接收节点 |
| 返回 | 本次结果、实际返回数据或沿用关联、结果边界、当前调用点的接收位置 |
| 接收／判断 | 来自哪里、使用哪些字段、具体条件对应哪条出线 |
| 定时及等待出口 | 事件来源、扫描取得的数据、状态与时间筛选；出口指向后续责任入口，不表示立即传参触发 |

- 参数按需写“业务含义／字段名、类型、必需或条件必需、来源”。区分调用时快照、锁内最新读取、持久化结果和派生判断；例如本轮 `notifyTimes` 与锁内最新次数不是同一个时点的值。不可取得的字段说明条件，不把查询失败后的未知值写成必有数据。
- 区分显式传参、返回值与沿用的调用上下文。原任务 ID、租户或批次上下文已在调用方保留时，写明沿用；不要为了表格完整虚构 DTO 字段、持久化批次 ID 或让同一对象重新创建。普通内部步骤只说明实际读取或改变的字段。
- 目标结果分类可按业务名称表达；类型、字段名和枚举编码未定时标“目标契约／命名待定”。已核实的数据库状态值与拟议方法返回类别分开，不能把 `void` 方法写成已有分类 DTO，也不能仅因尚未编码否定设计。成功、未决、跳过和异常的结果边界写清，例如“次数失配”不证明通知成功，保存失败不能返回已提交的新次数。
- 承接位置写到“流程名 → 节点名（稳定 ID）”，并逐项核对当前 `call.returns`、`source`、`target` 和接收节点出线。公共返回按实际调用上下文；可以列当前调用点映射，不能据此给模块写死一个外部目标。固定跨图输出则保留真实目标。
- 定时入口输入是独立触发事件及配置上下文；候选记录来自本轮查询。等待出口留下原对象和持久化依据，关联只指明后续入口，不应写成给定时器同步传入一笔任务、返回扫描判断或立即再次执行。
- 保存后成对核对“调用方提供 → 入口使用 → 返回产生 → 接收分流”：身份及类型一致、条件必需明确、每类结果有真实去向，读取失败与无记录分开。只改说明时复用既有画布证据，CLI 回读确认说明关联到正确节点；保留用户备注和有效历史，过时口径明确替代，避免多份当前契约相互矛盾。

示例：通知跳过返回的结果是“本轮执行依据过时”；原通知 ID 可沿用调用上下文，两次读取次数是判断依据。接收方按原 ID 重读当前记录，分别处理可重试、成功、耗尽或读取故障；不得把锁内次数直接当作业务完成结果。

### 关系两端的对应标签

建图时按[固定对应标签与逐级反查](evidence-to-change.md#固定对应标签与逐级反查)选择承接节点、填写成对字段。入口和出口之间的事实标识稳定，调用点及对端由原生引用定位。一次实际调用在返回之前仍需执行的解析、写入、确认或账实核对须留在路径上。

对 CLI 草稿执行 `python3 scripts/pair_labels.py 草稿.json`。加 `--at 流程ID 节点ID` 看双向来源及对应名称，加 `--report 核验.json` 导出逐对清单。跨主题时传入两端的草稿。可选的 `--out 新草稿.json` 仅把已经人工定义的唯一源端标签补到明确的接收端。首次绘制、同端多标签或存在歧义时，先按源码在草稿上选定对应事实。核验完成后使用流程 CLI 保存，再对回读执行相同检查。

### 跨图出口数据与编辑

节点类型 `output`，可选 `target: { entryPath, flowId, nodeId }`；完整出口必须关联其他流程的具体节点。当前面板选择范围为同需求的其他流程。未关联或目标失效要显示提示；点击节点仍是选择，显式“前往承接节点”才导航。切换为其他节点类型清除出口关联。

Mermaid 为兼容通用查看器使用步骤外形加 `%% workbench-output {"id":"next","target":{...}}` 注释保存出口元数据；工作台导入恢复专用形状和目标，不要删除该注释。外部 Mermaid 渲染器不会渲染专用出口形状，需准确形状时导出 SVG。新节点尚未关联时 target 为 null；不得把未关联当作已完成交付。


### 入口、事件与结束范围数据

- `input`：`source: {entryPath, flowId, nodeId}`，必须关联其他流程具体节点；未关联可存草稿但提示待关联。
- `event`：`eventType` 为 message/timer/manual/response/unspecified；`eventPhase` 为 trigger/intermediate。source 可关联本图其他节点或其他流程节点；没有图中来源时在原业务名称/说明中保留调度者或人工入口，不捏造引用。
- `end`：`endScope` 为 execution/subprocess/business/terminate/unspecified。旧节点未设置时显示“结束范围待明确”，不自动认定业务完成。
- 入口提供查看来源与返回入口；事件类型、阶段及结束范围直接呈现在画布，SVG 共用同一渲染逻辑。Mermaid 通过 `%% workbench-node {"id":"...","type":"input|event|end",...}` 保留元数据；外部 Mermaid 查看器只展示兼容外形，精确形状使用 SVG。
- 图中双边框事件表示原处理继续；单边框事件表示触发处理。输入关联、事件阶段和结束范围不改变业务执行，仅表达所核实的语义。切换节点类型清除不适用字段，迁移保留原节点、边、说明和版本。

### 并行与汇合

`type: gateway`，`gatewayMode: split | join | merge | unspecified`。工具栏添加或切换为该类型时初始为 split；导入缺失模式保留 unspecified 并提示。模式显示在画布和属性中；连线数量不符显示结构提示，允许保存草稿。Mermaid 的 `workbench-node` 元数据保存 gatewayMode；SVG 使用同一图形和模式文字。

### 公共定时入口与历史关联兼容

- 公共定时流程使用与其他目标相同的跨图出口 `output.target`。调用处不设置专用恢复类型或等待模式；进入公共流程后，由事件类型、调度触发和状态/时间查询条件表达执行规则。
- 属性面板统一选择“承接节点”并“前往承接节点”；目标反向列出各来源。Mermaid沿用 `workbench-output`，SVG沿用出口形状，AI上下文跟随普通target读取公共图。
- 旧 `recovery` 字段仅作历史兼容，不再作为新绘图规则；已有旧关联使用同一承接选择和跳转，不显示独立控件或恢复标记。迁移不能改写历史版本或丢掉有效来源；普通业务步骤有其他出线时不机械改为出口。
