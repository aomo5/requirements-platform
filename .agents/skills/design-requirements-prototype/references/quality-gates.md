# 页面设计与 H5 原型质量门禁

完成原型后逐项核对。只重跑受修改影响的验证范围。

## 1. 产物与目录

- [ ] 原生画板保存到正确需求主题；静态 HTML 和图片附件位于 `requirements/{模块}/{功能}/原型设计/`。
- [ ] 未创建独立前端项目，未修改正式业务代码。
- [ ] 任务包含文档维护时，按当前存储方式更新 `规格索引.md` 的原型入口、日期、阶段与下一步；只改页面的任务按授权范围交付原型。
- [ ] 使用工作台原生设计时，已检查 CLI 差异、服务端 dry-run 和保存回读；已有元素说明、需求关联及流程页面引用没有新增断链。
- [ ] 原型明确区分评审控制区和正式业务页面。
- [ ] Mock 数据、条件能力和未实现能力均有清晰说明。

### 页面合并或删除（适用时）

- [ ] 已淘汰画板、旧 HTML 源稿和原型页面集合中的重复页已实际移除，当前目录未以改名、隐藏或归档方式继续保留另一套入口。
- [ ] 旧页独有的字段、操作、异常、权限表现和有效说明已有承接；必要状态仍可查看，用户要求保留的对照资料未误删。
- [ ] 保存后核对实际画板列表与源原型列表，流程引用、当前导航及返回路径均指向保留页面，需求关联没有丢失。

## 2. 代码与现状证据

- [ ] 找到至少一个同端相似真实页面作为结构参考。
- [ ] 核对页面路由、菜单入口、权限标识和接口接入状态。
- [ ] 区分真实实现、Mock、未注册页面、空文件和待开发能力。
- [ ] 记录复用点、改造点、缺口和兼容风险。
- [ ] 未把需求目标误写成当前系统现状。

## 3. 视觉一致性

- [ ] 页面外壳、主色、背景、字体层级和内容边距与参考页一致。
- [ ] 表格、表单、按钮、弹窗、抽屉和卡片密度与现有系统一致。
- [ ] Web 与移动端分别遵循各自现有组件和导航习惯。
- [ ] 图标来自现有资产或合适图标库；不存在 emoji、ASCII、文本符号、手写 SVG 或 CSS 假图标。
- [ ] 参考截图与原型截图在相同 viewport、相近页面状态下完成并排检查。
- [ ] 已检查错位、裁切、留白、圆角、阴影、文字粗细和边框差异。
- [ ] 业务表格单元格没有默认堆叠第二行灰色注释；必要上下文已拆为列、标签、提示或详情。
- [ ] 主数据表是记录/对比页的视觉重点，没有被重复卡片、说明条或过多颜色抢占。

建议保留一份简短的视觉差异记录：

| 比较项 | 参考证据 | 原型结果 | 处理 |
| --- | --- | --- | --- |
| 页面壳与栅格 | 相似真实页面 | 一致/差异 | 已修正/有意差异 |
| 色彩与字体 | CSS Token/截图 | 一致/差异 | 已修正/有意差异 |
| 组件密度 | 表格/表单/卡片 | 一致/差异 | 已修正/有意差异 |
| 导航与图标 | 现有资产 | 一致/差异 | 已修正/有意差异 |
| 响应式表现 | 目标 viewport | 通过/失败 | 修正说明 |

## 4. 交互与核心流程

- [ ] 主导航、页面切换和返回路径可用。
- [ ] 主 CTA 能完成核心流程，不是只有视觉状态。
- [ ] 表单步骤、校验、确认、成功回执和列表结果形成闭环。
- [ ] 筛选、标签、开关、弹窗和抽屉至少覆盖评审所需状态。
- [ ] 场景切换会真实改变页面数据或权限表现。
- [ ] 页面刷新或 hash 直达后仍能进入指定页面。
- [ ] 记录列表直接展示可比较的原始数值，业务对象可进入按时间排列的历史数据。
- [ ] 新增/编辑关联对象提供真实可操作的搜索、勾选/移除和已选数量，不是静态标签演示。

### 复杂规则与异步场景（适用时）

- [ ] 输入、允许值及规则有明确来源和版本；沿用已有 Apifox 定义，区分样例、源码现状与拟议调整。
- [ ] 对声明范围检查越界、遗漏、冲突和输出承接；问题给出具体输入或区间及相关规则，未验证范围如实记录。
- [ ] 场景会改变输入并经规则推进；可追到命中条件、结果和下一接收方，等待时可识别真实触发与超期处理。
- [ ] 现状与方案的差异、独立演练状态及受影响用例可区分；切换版本不会沿用不兼容的旧演练轨迹。
- [ ] 原型演练、规则检查、用例关联及实际业务执行分别报告，未由模型通过推断业务测试通过。

### 存量页面兼容验收

以现有页面和实际接入的源码为基线，逐项核对受本次改动影响的页面。

- [ ] 列表保留原筛选项与控件、列与状态、勾选、行内和批量操作、记录入口及分页。新增列或展开项后，在目标宽度检查原固定列、操作区和表格滚动。受影响的空列表、只读状态也按原有显示条件核对。
- [ ] 普通菜单、列表进入详情及普通详情直达的默认视图与现有页面一致。详情、记录、新增和编辑沿用原来的页面、弹窗或抽屉及返回方式。新功能专用入口定位到对应区域。
- [ ] 从原页签进入新区域再返回，以及详情返回列表后，筛选状态、对象归属和原有操作符合现有交互。
- [ ] 对本次涉及的原有指标与新增指标分别核对来源、权限及展示区域，页面改动均有对应功能需要。

在保存后的原型中各走通一条代表性旧路径和新增路径。用旧记录从原入口按原条件查询、打开详情，有导出时核对原字段、数据范围和数值。新增展示列或展开内容是否纳入导出，按已确认的需求处理。用新记录核对新增能力，涉及统计时检查来源、数据归属和统计时间。两次操作涉及同一笔钱或同一对象时，用同一个样例对齐明细、汇总及导出，检查每个指标只计一次。

## 5. 权限与数据边界

- [ ] 菜单、动作、数据范围和登录端分别表达。
- [ ] 默认权限、可授予上限、条件授权和禁止权限可区分。
- [ ] 只读、禁用、隐藏和脱敏使用正确表现。
- [ ] 资金、删除、远程控制、授权等高危动作不会因普通业务权限自动开放。
- [ ] 多租户、上下级关系和数据归属不会仅靠前端筛选解释。
- [ ] 存量用户和历史数据的兼容路径已体现或明确排除。

## 6. 浏览器与响应式验证

- [ ] 从保存后的工作台画板或本地静态服务预览，资源均能加载。
- [ ] Web 页的目标 viewport 无非预期横向滚动。
- [ ] 涉及移动端或响应式时，目标窄屏（如 390px）无溢出、遮挡或按钮换行破坏。
- [ ] 控制台无 error/warning，页面无脚本异常。
- [ ] 关键按钮、表单和切换操作均实际点击验证。
- [ ] 修复视觉或交互问题后，仅重跑受影响场景并保留通过证据。

## 7. 交付说明

- [ ] 提供可点击的工作台画板入口或本地原型文件。
- [ ] 说明 Web、移动端及主要流程的覆盖范围。
- [ ] 说明关键权限边界和有意保留的未决项。
- [ ] 简述验证 viewport、核心路径和错误检查结果。
- [ ] 将最终验证页面留在用户选择的浏览器中供用户查看。
- [ ] 未经用户明确要求，不部署、不发布、不提交生产变更。

## 整功能收敛与增量可见性

- [ ] 本次功能内的菜单、页面、页签与弹窗归属一致；沿用页、增量页、新增页及合并页有清楚分工，无重复入口或虚构分组。
- [ ] 存量页右侧能看到当前改动说明；保留的旧功能与新增点可核对，业务页面不夹带内部改造说明。
- [ ] 同一配置从编辑到确认、保存、失败重试及重新进入值一致；跨页保留主体 ID、范围和权限。
- [ ] 列表汇总与详情个体状态匹配；多对象覆盖部分受影响，不能把只读权限等同于单对象范围。
