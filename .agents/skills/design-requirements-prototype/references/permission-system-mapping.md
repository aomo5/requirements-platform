# 权限体系取证、映射与全景页方法

当一个页面需要回答“不同账号怎么配置权限、实际保存什么、Web 和移动端最终出现什么”时，使用本方法。目标是用真实控件和逐项证据展开权限链路，而不是只画抽象角色框图。

## 一、先定义全景页要回答的问题

一张权限全景页至少应让评审者直接看明白：

1. 账号属于什么业务身份，它的可选权限池从哪里来？
2. 前端每个标签、树节点或 switch 实际绑定什么？
3. 一次操作保存一个菜单节点、一棵子树，还是一个会展开多个节点的权限组？
4. 哪些权限固定开启、默认开启、默认关闭可选或禁止？
5. Web 与移动端各自检查什么 permission，最终决定哪个菜单、页面或按钮？
6. 服务端是否同时检查动作权限、租户、数据范围和上下级边界？
7. 当前实现与已确认目标哪些一致，哪些是实现缺口或越权风险？

若页面不能回答这些问题，不要用“权限池、已选 N 项、某角色大概包含某模块”等摘要取代明细。

## 二、拆开容易混淆的概念

| 层次 | 回答什么 | 不能替代什么 |
| --- | --- | --- |
| 账号类型或业务身份 | 账号是谁，应进入哪个允许池和默认模板 | 不等于账号最终拥有全部模板权限 |
| 角色 | 有名称、可复用的菜单集合 | 不等于账号类型，也不等于数据范围 |
| 菜单大类或权限组 | 一个前端开关通过关联表展开哪些菜单 | 不能只用组名推断真实成员 |
| 用户直配菜单 | 直接保存到某个账号的菜单节点 | 不能忽略父节点补齐或其他权限来源 |
| 有效功能权限 | 角色、权限组和用户直配等来源合并后的真实动作 | 不自动扩大业务数据范围 |
| 数据权限 | 有权动作可以作用于哪些片区、站点或账户 | 不产生新增、编辑、删除等功能权限 |
| 上下级关系 | 当前账号可以管理哪些下级账号 | 不代表可以操作下级的全部业务数据 |
| 登录端 | 账号能否通过某端认证 | 不等于自动获得该端全部菜单 |

权限设计与原型至少同时呈现“能做什么、能做哪些数据、能管理谁”，不从任一层推导其他层。

## 三、按完整链路取证

对每种账号类型分别追踪：

    系统总菜单池
      → 租户套餐可用范围
      → 账号类型允许池
      → 当前操作人可授予上限
      → 固定 / 默认 / 可选 / 禁止
      → 前端控件与保存对象
      → 角色、权限组或用户直配产生的有效权限
      → Web 和移动端菜单/按钮条件
      → 服务端动作鉴权
      → 租户、数据范围和上下级校验

对每个前端控制器记录其基数关系：

- 直配标签：通常一个控件对应一个菜单节点，但保存时可能还要补齐父节点。
- 树形复选：父节点可能级联整棵子树；叶节点可单选并反向同步父状态。
- 权限组 switch：一个控件保存一个组 ID，服务端通过关联表展开多个菜单 ID。
- 平铺 switch：每个可操作 switch 通常只改一个菜单 ID，固定项只展示且不能关闭。
- 身份固定导航：可能由账号类型分支直接决定结构，但页面数据和页内动作仍需权限与数据范围校验。

Web 和移动端必须分别取证。两端即使提交同一字段，也可能使用不同候选接口、不同默认值和不同级联规则。

## 四、证据层级与口径

| 证据 | 适合确认 | 处理方式 |
| --- | --- | --- |
| 当前源码 | 候选接口、默认值、保存字段、前端条件、服务端鉴权 | 记录仓库、分支或 commit、文件与方法 |
| 运行配置或数据库 | 动态菜单、权限组成员、租户套餐和真实数量 | 优先只读接口或导出；未取得时标“待运行导出” |
| 当前运行页面 | 真实文案、控件数量、展开方式和初始状态 | 只读核对，不保存或修改真实账号 |
| 已确认需求 | 目标规则与验收口径 | 与当前实现分层展示，不用目标覆盖现状 |

不要按中文名称去重。同名菜单可能是不同 menuId，也可能分别用于不同端或不同父节点。数量只代表当前运行快照，不得写成永久业务常量。

## 五、建立逐动作台账

对最终会影响菜单、页面、按钮或接口的每个动作，至少记录：

| 字段 | 说明 |
| --- | --- |
| 模块与中文名称 | 评审者可以理解的业务动作 |
| 技术标识 | permission、menuId、categoryId 或 roleId；未取得时标待回填 |
| 配置形式 | 标签、树节点、权限组 switch、平铺 switch、固定导航或隐藏自动项 |
| 保存对象 | menuIds、menuCategoryIds、roleIds 等提交字段及展开方式 |
| 类型状态 | 固定、默认开启、默认关闭可选、高风险或禁止 |
| 新建与编辑 | 新建默认、编辑回显来源及缩权处理 |
| Web 映射 | 菜单、页面、按钮和无权处理 |
| 移动端映射 | 底栏、入口、页内按钮、身份分支和无权处理 |
| 服务端门禁 | 接口 permission 及数据范围、上下级校验 |
| 当前与目标 | 已实现、未实现、过度放行、前端错配或待确认 |
| 证据 | 代码、接口、运行数据或评审决策来源 |

“组”不能取代成员台账。权限组仍需列真实组名、组 ID、组内 menuId/permission 和展开来源；尚无运行数据时，展示准确回填链路，不根据组名编造成员。

## 六、动态权限组的快照与重置基线

当权限组成员保存在数据库或运行配置中、源码只包含查询与保存逻辑时，不要因此把某一账号类型的全部菜单长期标成“待确定”。先判断是否能在不改变真实权限的前提下取得只读快照：

1. 记录环境、读取日期、前后端版本或 commit，以及快照是否来自接口、运行页面还是数据库导出。
2. 同时导出权限组本身与成员关联，至少保留 `categoryId`、名称、基础/普通属性、`menuId`、permission、父菜单和适用端；不能只记录组名或成员数量。
3. 分开统计原始关联条数、去重后的 permission 数、菜单入口数和前端可见开关数。多组可包含同一 permission，同一 permission 也可能由多个 menuId 承载，不能混用这些数量。
4. 还原当前状态时，基础组成员通常对应“可拥有且新建默认”，普通组成员对应“可拥有但新建默认关闭”；未归入任何组的权限只能在该快照环境下判为不可拥有，不能外推到其他环境。身份固定导航应另按前端代码处理。
5. “按当前代码重置”实际是“代码版本 + 运行配置快照”的联合基线。快照结构或含义变化时，应同步升级草稿存储版本，避免浏览器里旧草稿覆盖新基线。
6. 直接展示异常配置：例如疑似测试命名的基础组、组名与真实成员语义不一致、普通组与基础组重复包含、前端总开关受分页限制。以真实成员为准，不按中文名称美化或猜测。
7. 快照只代表被读取环境。目标环境提测或上线前重新导出比较；不一致时先更新台账与重置基线，再做权限验收。
8. 涉及存量账号兼容时，快照不能只导出菜单关系，还要做不暴露账号明细的聚合不变式检查：账号类型与历史身份标记是否一致、固定基础组是否缺失、自身节点/直接上级/祖先闭包是否完整、启用账号是否满足当前启用前置条件。
9. 页面用创建人、名称或默认值作展示兜底，不等于数据已经迁移。应继续核对服务端鉴权、下级统计和业务数据范围实际读取哪张关系表；将“代码可触发但快照未命中”和“快照已有命中记录”分开标注。

若无权取得安全的只读运行数据，才将相关项标为“待运行回填”，并同时写清接口链路、关联表、所需字段和负责回填的环境；不要把“没有静态证据”误写成“当前关闭”或“系统没有权限”。

## 七、全景页的信息设计

- 默认先展示所有账号类型的具体控件和逐项台账，让评审者不必先理解抽象模型。
- 顶部评审控制只保留“当前代码 / 需求落地后”等口径切换；账号类型放内容区筛选，避免看起来像系统配置。
- 筛选只隐藏其他账号类型，不增加会隐藏模块、状态或关键字明细的二级筛选。
- 表格依次展示中文动作、技术标识、默认状态、前端控制器、终端效果、服务端门禁和当前/目标差异。
- 抽象集合关系只做辅助说明，不占据首屏或取代具体权限。
- 同名权限、隐藏基础项、固定导航、一对多权限组和前后端错配必须直接显示。
- 数量摘要可作对账快照，但必须能回到逐项成员，并标证据日期与版本。
- 正式账号创建页保持现有产品风格和简洁交互；技术标识、差异结论和全量台账放评审全景页。

## 八、必查的兼容与实现缺口

- 新账号默认模板不得在普通编辑时重新覆盖用户原选择。
- 编辑页只加载本次候选池时，不得静默删除历史有效但当前不可见的权限。
- 收窄上级权限或数据范围前，检查超出新上限的下级，不能静默造成越权或突然丢权。
- 前端隐藏只是体验门禁；服务端仍需检查 permission、目标账号下级关系和业务对象数据范围。
- 账号类型、历史身份标记和角色来源并存时，必须找到统一有效身份与有效权限的服务端口径。
- 列表为了兼容旧数据所做的展示回退，不能替代直接上级与祖先闭包迁移；所有管理校验、下级统计和缩权检查必须读取同一套关系事实。
- 身份固定导航不得绕过页内动作权限和数据范围。
- 对照前端按钮与后端接口，检查：前端可见但接口拒绝、前端隐藏但接口放行、允许池返回需求禁止项、需求可选项在允许池中不可达。

## 九、最小验收

1. 默认视图直接看到所有账号类型的具体控件和明细。
2. 每种账号类型筛选后，完整台账和对应终端映射仍在。
3. 逐项成员数与分组摘要可对账；运行快照标明环境、日期、版本与原始关系数，未取得运行数据的字段显式待回填。
4. Web 与移动端的控件、保存对象、默认值和页面效果分开记录。
5. 当前实现与需求目标可并列比较，实现缺口不被目标口径掩盖。
6. 桌面和窄屏均可阅读；宽表只在自身容器滚动，页面不整体横向溢出。
7. 所有差异均能回到源码、运行配置、运行页面或已确认需求之一。
