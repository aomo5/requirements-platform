# 质量与维护

## writing · 界面文字

先问这段文字提供什么新增判断信息。如果删掉后仍能知道当前位置、下一步和结果，就删除。

### 取舍示例

| 情况 | 处理 |
| --- | --- |
| 已在某个需求中，列表再写“本需求” | 删除，当前标题已表达上下文 |
| 每个菜单后跟一句解释用途 | 用准确名称与分组表达；按需放帮助 |
| “已写／待写”等状态已有明确图形 | 使用状态图标，悬停或所在行键盘聚焦显示短名称；不常驻同义文字 |
| 多个业务状态无法用图形准确区分 | 保留具体状态名，避免必须逐项悬停猜含义 |
| “选择页面再点击元素”长期挂着 | 只在进入选取模式时提示 |
| 状态、辅助标识或紧凑工具已有清晰图标，旁边仍写同义文字 | 移除多余文字，保留悬停／聚焦名称和可访问名称 |
| “完成”“关联流程”“恢复”等正常任务按钮被换成单个图标 | 恢复文字按钮，让用户直接知道动作及结果；不以图标数量作为精简目标 |
| 空页面只有一个加号，无法清楚知道如何开始 | 用“新建页面”等文字按钮作为主入口，列表标题旁的新增仍可用加号 |
| 用户录入的需求依据或备注 | 保留，这是任务内容 |
| 保存失败、字段限制、危险后果 | 贴近发生位置保留，并给出动作 |

说明不能替代顺畅操作。先检查入口、上下文、返回位置和保存时机，不机械把冗余说明改成 tooltip。设计原因和内部流程写入规范，产品用户只看到对当前任务有用的信息。

## accessibility · 键盘与可读性

### 可读性

必要小字号文字与背景对比度以 4.5:1 为本系统目标；边界、图标与焦点按用途检查，不能只看十六进制值。禁用内容可降低强调，但正常标签不能使用禁用样式。配色有文本或图标共同表达。

浅蓝 #0d99ff 适合强调标记；白字小按钮改用 action-primary。tokens 校验检查默认、悬停、按下及主要文本配对，不能代替实际字体渲染和可用性检查。

### 键盘

主要操作可 Tab 到达；按钮 Enter/Space，披露 aria-expanded，选择 aria-selected 或 aria-pressed。图标动作与状态具有可访问名称，聚焦时也能看见简短提示。只读状态不增加虚假按钮；在其所属行聚焦时展示提示，并纳入该行的可访问名称。关闭浮层恢复焦点，重绘不丢焦点，快捷键不劫持输入。

### 小屏与动效

选择一个实际使用的窄屏断点，检查被隐藏工具的替代入口、滚动和主要按钮。reduced-motion 下去掉位移与缩放。不能为了容纳三栏把所有文字和点击目标缩小。

## review · 验收与维护

### 本次改动如何验收

| 检查 | 通过证据 |
| --- | --- |
| 字体与颜色 | 检查实际 computed style 与前景/背景配对 |
| 组件状态 | 默认、悬停、按下、焦点、禁用、处理中有明确反馈 |
| 内容 | 长标题、真实文案、异常和空态可读、无裁切 |
| 操作链 | 入口、结果、返回、状态与输入连贯 |
| 文案精简 | 每条常驻说明有独立用途，无重复上下文 |
| 保存 | 修改、立即切换、失败恢复、重开保留符合实际能力 |

只检查本次涉及的组件和路径，复用未变化的通过证据。测试业务写入优先用独立样例，不污染真实需求。截图证明外观，实际操作证明交互；两者不能互相代替。

### 图标检查范围

一次工作台检查覆盖主工具栏、侧栏、空状态入口、对象卡片、动态列表，以及预览、源码、版本、关联选择、备注和确认弹窗。逐项判断操作、状态标签和辅助描述的用途：既检查“已写／待写”等可用图标的状态，也检查完成、确认、关联等按钮是否被过度图标化。确认没有字符图标、重复原生 title、缺少名称或动态重绘后错误的控件形式。保留具体对象名称、真实数量、清晰的任务按钮和必要后果。

至少实测一个工具选中切换、一个键盘提示、一个弹窗内提示、一个动态列表操作和一个窄屏。需求关联改动再验证从原文到元素、切状态及返回原文的焦点与保存；只使用隔离数据进行写入。

### 规则的唯一来源

references 是规范正文，tokens.json 是值的来源，tokens.css 和可视手册由生成脚本输出。修改后运行 validate 和 build，同步更新项目规范索引；不要同时手改多份参数表。

现有项目有特殊用途时，记录具体场景、差异和原因。一次局部反馈先判断是否可复用，避免把单页例外扩成全局禁令。

### 当前发布范围

1.0 提供浅色基础变量、五类组件规范、四类工作台交互模式、验收规则及可操作手册样例。它是可复用的规范和技能基础；生产组件库、暗色主题、Figma 变量库及工作台逐组件迁移需在对应任务实施后记录，不能仅凭文档存在标为完成。
